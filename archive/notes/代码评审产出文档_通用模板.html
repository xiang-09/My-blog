代码评审产出文档 · 通用模板 ​

说明：本模板为可复用骨架。换评审范围/换人时，只需替换三处——①「规定范围」、②「分级与修复计划」的责任划分、③「五步法逐条复核」的具体实例。其余骨架、表格列名、五步法结构原样复用。

一、评审概况（信息表） ​

项目内容
课程 / 任务【填写】
姓名 / 学号【填写】
评审对象【类名 / 模块 / 文件】
评审方法【AI 扫描 + 人工复核 / 结对评审 / 走查】
规定范围【本次评审关注的坏味道类型 / 维度 / 规则】
最小修复数【minFix 计算规则与结果】
日期【填写】

二、评审依据（本次规定的标准） ​

本次评审按【规定范围】执行，标准维度如下：

维度编号维度名称判定依据
D1【维度1】【说明】
D2【维度2】【说明】
D3【维度3】【说明】
D4【维度4】【说明】
D5【维度5】【说明】

注：如果当次没有「五维」要求，就把这一节换成当次给定的分类标准，例如「代码规范 / 性能 / 安全 / 可维护性」等。

三、扫描总表 ​

AI 扫描 + 人工复核后，共识别【N】个问题：

序号位置类型严重度责任归属依据标准
①【类.方法 / 行号】【坏味道类型】高/中/低本人 / 遗留 / 不得修改【对应维度】
②……………
③……………

四、分级与修复计划 ​

按本次规定范围，将问题分为三类：

类别说明序号
本人负责修复【本次规定的主坏味道 / 次坏味道】①②③
识别但保留为遗留【本次不要求改的类型】④⑤⑥⑦
不得修改区域【题目/规范禁止改动部分】—

修复目标： 至少修复【minFix】处本人负责的问题。

五、逐条复核（五步法） ​

对每个本人负责的问题，按以下五段式写：

问题 ① ​

  1. 问题定位 【哪个类 / 哪个方法 / 哪一行 / 哪段逻辑】

  2. 问题描述

    • 现象：【当前代码表现出的问题】
    • 触发条件：【什么输入 / 什么场景会暴露】

  3. 依据标准 【对应本次规定的哪个维度 / 哪条规则】

  4. 修复建议 【怎么改、改成什么样、用什么重构手法】

  5. 验证方式 【跑哪条用例 / 看哪个断言 / 观察哪个输出】

问题 ②、③ … 同上结构重复即可。

六、行为不变性说明（关键证明段） ​

重构前后需证明「行为契约未被破坏」。写法：

传入【测试数据】→ 原逻辑输出【X】→ 重构后保留【关键闸门 / 判断条件】→ 输出仍为【X】→ 与断言 / 预期一致。

如果当次没有断言，就写：

重构仅改变【结构 / 命名 / 组织方式】，未改变【输入输出关系 / 业务判断条件 / 返回值】。

七、修复统计与归档 ​

指标值
识别总数【N】
已修复【M】
遗留【N - M】
是否满足 minFix【是 / 否】

归档行（机器可校验）：

REVIEW|识别总数|已修复|遗留

八、重构后代码快照（可选） ​

java
// 修复①：【说明】
// 修复②：【说明】
// 修复③：【说明】
【重构后的方法代码】

套用口诀 ​

信息表定身份 → 标准定维度 → 总表列问题 → 分级切责任 → 五步法逐条写 → 数字走查证行为不变 → REVIEW 行收尾。

换评审范围时，只需要替换三处：

  1. 「规定范围」：换成当次要求的坏味道类型或维度；
  2. 「分级与修复计划」：按当次规则重新划分本人 / 遗留 / 不得修改；
  3. 「五步法逐条复核」：把具体位置、现象、依据换成当次实例。

其余骨架、表格列名、五步法结构都可以原样复用。
